# Dockerfile installs requirements.txt only and names each file it copies, so nothing listed
# here reaches the artefact, and .dockerignore keeps `tests/` — what these packages exist to
# run — out of the build context (ci/smoke.py check (d) is what enforces that).
# Install with:  pip install -r requirements-dev.txt
#
# Annotate a requirement with WHAT BREAKS WITHOUT IT, not with what the package is. The line
# earns its place on a test-only dependency whose absence is an ImportError at collection
# rather than a failed assertion: in CI that reads as an entirely red suite whose message
# names a missing module and says nothing about this project, and a word here is the shortest
# route from that message back to `make install`.
-r requirements.txt
