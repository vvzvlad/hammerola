# Проверка скилла hammerola на прошлых сессиях

Скилл `skill/SKILL.md` переписывали после конкретных провалов в прошлых
сессиях. Здесь — прогон, который проверяет, меняет ли правило ход агента:
свежий Claude Code получает момент той сессии, где агент свернул не туда, и
оценивается его первый ход — первый ответ, первый бриф или первый файл
геометрии.

## Как устроен прогон

- `scripts/window.py JSONL FROM TO OUT` — вырезает из транскрипта окно
  переписки до момента сбоя в `OUT/dialog.txt` (реплики `[user]` / `[assistant]`
  дословно) и сохраняет показанные в нём картинки в `OUT/images/`.
- `scripts/run_case.py CASE RUN skill|noskill` — распаковывает проект на
  коммите момента сбоя (без последующей истории), запускает `claude -p` с
  репликами одним сообщением и картинками; в режиме `skill` сообщение начинается
  с `/hammerola`, в `noskill` инструмент `Skill` закрыт. Клиент hammerola,
  субагенты и logovo закрыты; системная приписка просит остановиться на первом
  ходе.
- `scripts/digest.py RUN` — что агент сказал и сделал, по порядку.
- `scripts/skill_after_compact.py JSONL...` — где скилл вошёл в сессию, где
  было сжатие контекста и сколько скилла вернулось после него.

`cases/` (дословные реплики и фото) и `runs/` (потоки прогонов) лежат только
локально: репозиторий публичный.

## Что видно

- **Вопрос задаётся, остановки нет.** Правила «скажи назад» и «спроси
  инструмент» срабатывают вопросом, но в том же ответе агент продолжает с
  допущением по умолчанию (c1 skill-2, c4 оба). Ни в одном правиле нет слов
  «и закончи ход».
- **Пример из скилла становится фактом проекта.** В c3 skill-1 строка из
  описания чужого случая попала в SPEC.md как решение владельца.
- **Цена и ссылка не появились ни разу** (c2, 0 из 3), хотя решение «купить»
  верное во всех трёх — его подсказывала сама реплика владельца, поэтому этот
  случай правило не проверяет.
- **Половина скилла пропадает после сжатия контекста.** В интерактивных
  сессиях Claude Code 2.1.296 вызванный скилл возвращается после
  автоматического сжатия обрезанным до 20 000 знаков — для текущего скилла это
  строки 1–386 из 833 (сессия 86bb1373 в ukuetis-controller-hw, 2026-10-15).
  В трёх найденных сессиях агент после обрезки скилл заново не прочитал, в
  одной из них обрезанный текст прошёл пять сжатий. В `claude -p` 2.1.277
  скилл после сжатия не вернулся вовсе.

## Ограничения

- По одному-два прогона на режим: это наблюдения, не частоты.
- Момент сбоя подан одним сообщением с цитатой переписки, а не настоящими
  ходами; системная приписка («первый ход», «субагентов нет») меняет условия.
  c3 skill-1 её не послушал и сделал всё целиком.
- В b приписка запрещала «другие копии проекта на диске» — это могло отговорить
  агента искать `formwork.f3d` вне репозитория.
- Проект восстановлен по коммиту; незакоммиченное состояние того момента
  потеряно. Для c1 проекта в git тогда не было — только картинки из окна.
